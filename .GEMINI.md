# Правила разработки проекта WhereMyMoney («Где мои деньги»)

Данный файл содержит обязательные правила и стандарты для AI-ассистента и команды разработки.

---

## 1. Главный рабочий процесс: Plan-First (Сначала план — потом код)

* **Обязательное согласование перед реализацией**:
  Перед внесением изменений в код или реализацией новой функциональности сформулируй четкий пошаговый план (Task Breakdown).
* **Ожидание подтверждения**:
  Не начинай кодить объемную фичу, пока пользователь не подтвердит план или не внесет в него коррективы.
* **Итеративность (Thin Slices)**:
  Разбивай задачи на небольшие верифицируемые шаги. После каждого шага код должен компилироваться (`flutter analyze` без ошибок).

---

## 2. Стандарты дизайна (Taste Skill & Anti-Slop)

* **Никакого шаблонного дизайна («AI-slop»)**:
  * Запрещены дефолтные тусклые фиолетовые градиенты, шаблонные 3 одинаковые карточки и серые невыразительные списки.
  * Ориентир стиля: **Премиальный Fintech** (Linear + Revolut + Apple Wallet).
* **Параметры дизайна (Core Dials)**:
  * `DESIGN_VARIANCE: 6` — строгая финансовая логика с выразительной асимметричной карточной иерархией.
  * `MOTION_INTENSITY: 5` — плавные, тактильные микро-анимации нажатий, аккуратные bottom sheets, анимированные числа.
  * `VISUAL_DENSITY: 5` — информативный, но дышащий дашборд; акцент на ключевые цифры (крупный баланс, контрастные суммы).
* **Цветовая палитра**:
  * Темная тема (Obsidian & Deep Slate): `#0A0E1A`, `#131B2E`, `#1E293B`.
  * Акценты: Изумрудный доход (`#10B981`), кораллово-красный расход (`#F43F5E`), индиго/электрик для служебных действий (`#6366F1`).
* **Скорость UX**: Ввод транзакции должен занимать не более **3 секунд** (минимум кликов, удобный numpad, мгновенный выбор категории).

---

## 3. Архитектура и стек технологий

* **Фреймворк**: Flutter (версия 3.x+) с Dart 3 null-safety.
* **Платформа**: В первую очередь Android (с возможностью быстрого запуска под Windows Desktop для отладки).
* **Слои приложения (Clean Architecture / Feature-First)**:
  1. `core/` — тема, токены, утилиты, форматирование валюты/дат.
  2. `data/` — локальная БД (SQLite via `sqflite`), модели данных, мапперы, репозитории.
  3. `domain/` — бизнес-логика (при необходимости сложных расчетов).
  4. `presentation/` — экраны, виджеты, стейт-менеджмент (`Provider` / `Notifier`).
* **Local-First принцип**:
  * Все операции выполняются локально и офлайн мгновенно.
  * Каждая сущность генерирует `UUID` (не auto-increment integer ID), сохраняет `created_at`, `updated_at` и флаг `is_deleted` для будущей бесшовной синхронизации с сервером (Supabase / PostgreSQL).

---

## 4. Качество кода и тестирование

* **Линтинг и анализ**: Перед завершением задачи всегда запускать `flutter analyze`. Никаких игнорируемых предупреждений без веской причины.
* **Импорты**: Использовать `package:where_my_money/...` для внутренних модулей.
* **Чистота виджетов**: Выносить переиспользуемые UI-компоненты в отдельные файлы; не создавать монолитные build-методы на 500 строк.

---

## 5. Контроль версий и GitHub (Git Workflow)

* **Коммит и пуш после каждого этапа**: После успешного завершения каждой фазы дорожной карты (или крупной логической подзадачи) и прохождения `flutter analyze`:
  1. Создавать понятный, осмысленный коммит по conventional commits (`feat: ...`, `fix: ...`, `refactor: ...`).
  2. Выполнять `git push origin main` в репозиторий на GitHub.
